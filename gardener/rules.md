# Gardener Rules

## Protected Modules

- `src/domain/achievements.ts` because Derives streak and time achievement unlocks from the calendar, which the spec requires to be recomputed deterministically and never from the current date.
- `src/domain/flames.ts` because The flame catalog is the single source of truth for flame identity, palette, rarity, and unlock achievement; visual profile edits must preserve unlock conditions and data shape, so changes need human review. (from specs/004-flame-visual-profiles/plan.md#Implementation Plan: Flame Visual Profiles)
- `src/components/Bonfire/flameModel.ts` because The intensity curve (1 - e^(-s/14)) and height/glow mappings define the flame visuals and must be preserved. (from specs/001-bonfire-productivity-tracker/plan.md#Phasing)
- `src/hooks/useSettings.ts` because Loads and persists the selected flame and color, which must survive restarts with Amber as default and must not drop unsaved scores during load.
- `src/theme/palettes.ts` because Flame palettes are a single source ported from the design and must stay in sync with it. (from specs/001-bonfire-productivity-tracker/research.md#Phase 0 Research: Bonfire Productivity Tracker (design-fa...)
- `src/components/Calendar/ScorePickerBar.tsx` because Owns score button colors from the shared heat-ramp token source and enforces the locked-flame selection guard, both spec-defined behavior.
- `src/components/Settings/FlameGallery.tsx` because Implements the locked-flame selection guard at gallery level, where locked flames must be visibly rejected and not equipped.
- `src/screens/BonfireScreen.tsx` because Enforces screen-level active flame checks and the swipe-up calendar gesture, which must not break taps or scrolling elsewhere on the screen.
- `src/components/Calendar/CalendarSheet.tsx` because Contains the calendar gesture surfaces and month paging limits (no future months) that the spec fixes exactly.
- `src/domain/fire.ts` because Core fire engine governs the product's central mechanic (cumulative strength, reset on extinguish); changes need human review. (from specs/001-bonfire-productivity-tracker/contracts/fire-engine.md#Contract: Fire Engine (`src/domain/fire.ts`))
- `src/data/entriesStore.ts` because Persistence of user daily scores under a versioned key; changes risk data loss or incompatible migration and need review. (from specs/001-bonfire-productivity-tracker/contracts/entries-store.md#Contract: Entries Store (`src/data/entriesStore.ts`) & `u...)
- `src/data/settingsStore.ts` because Persistence of user settings under a versioned key; changes need review to avoid breaking stored preferences. (from specs/001-bonfire-productivity-tracker/contracts/settings-store.md#Contract: Settings Store (`src/data/settingsStore.ts`) &...)
- `src/domain/dates.ts` because Local-date helpers and the today-not-missed boundary are behavior-critical and need human review. (from specs/001-bonfire-productivity-tracker/plan.md#Constitution Check)
- `src/components/Bonfire/Flame.tsx` because The Skia flame must keep design fidelity to BonfireDesign screenshots and the 120 FPS performance target; changes need review. (from specs/001-bonfire-productivity-tracker/research.md#Phase 0 Research: Bonfire Productivity Tracker (design-fa...)
- `src/theme/tokens.ts` because Theme tokens are a single source ported from styles.css and must stay in sync with the design. (from specs/001-bonfire-productivity-tracker/research.md#Phase 0 Research: Bonfire Productivity Tracker (design-fa...)
- `src/components/Bonfire/Embers.tsx` because Particle rendering is on the performance-critical render path and must not break frame rates or obscure controls. (from specs/004-flame-visual-profiles/spec.md#Functional Requirements)
- `src/hooks/useEntries.ts` because Enforces score validation (1..5, no future dates) and ordered persistence, and derives fire via useMemo; contract-mandated behavior lives here.
- `jest.setup.js` because Global test environment setup (including AsyncStorage mocking the contract tests rely on); changes can make all tests pass or fail spuriously.

## Never-Touch Paths

- `specs/**` because Product specs and contracts are the authoritative statement of scope and fix policy, so automation must not edit them.
- `gardener/**` because This is the maintenance tool's own configuration and policy area, so automated changes must not modify it.
- `BonfireDesign/**` because BonfireDesign/ is the read-only canonical design reference and must not be modified. (from specs/001-bonfire-productivity-tracker/plan.md#Constitution Check)
- `**/.env*` because secrets must never be modified by Gardener.
- `**/secrets/**` because secret material requires human handling.
- `GARDENER.md` because Gardener's own rules change only through a reviewed constitution PR.
- `.agents/skills/**` because Agent skill files define project workflow instructions and are not application code.
- `.claude/skills/**` because Agent skill files define project workflow instructions and must stay in sync with the spec kit tooling.
- `src/data/**/v1 storage key literal` because The versioned AsyncStorage key is the migration anchor for saved scores; renaming it without a migration loses user data.

## Autonomous Fixes Allowed

- `lint_format`: kept from the current constitution
- Under the current no_autonomy classification, make no autonomous code changes; only report findings.
- If autonomy is later permitted, limit to prettier formatting and eslint --fix on non-protected files under src/components/Settings or __tests__ with no behavior change.

## Assisted Fixes Allowed

- `dependency_patch`: kept from the current constitution
- `tests`: Adding tests for pure domain logic (fire recompute, achievement unlocks, flame catalog ordering) changes no runtime behavior and directly checks spec rules
- `complexity_reduction`: Splitting the Bonfire scene, Flame, or Embers components touches rendering and animation paths that need human review for visual and frame-rate regressions
- Type-level fixes under strict TypeScript that preserve runtime behavior in src/components and src/hooks, reviewed by a maintainer.
- Adding missing unit tests for contract guarantees (for example, fire.ts behavior table rows or settingsStore invalid-color fallback) without changing production logic.
- Dependency patch updates for jest-expo, eslint-config-expo, or @types packages, verified by the full test run.

## Advisory-Only Areas

- `api_behavior`: The persisted AsyncStorage keys and settings-store contract are read on every launch, so schema or key changes should be advised on, not auto-applied
- Fire scoring rules (gap tolerance, strength contribution curve, extinguish policy) because they are product decisions defined in the spec.
- Skia and Reanimated rendering performance on device, which needs manual inspection.
- Achievement thresholds and unlock timing for collectible flame styles.
- Fire Health labels (Faint, Steady, Bright, Radiant) and atmosphere tuning from local time.
