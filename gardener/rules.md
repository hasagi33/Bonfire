# Gardener Rules

## Protected Modules

- `src/domain/fire.ts` because Fire engine derives strength, extinguishing, and relighting from all entries; the contract requires deterministic, order-independent results.
- `src/domain/achievements.ts` because Achievement evaluation decides streak and time flame unlocks, so errors would lock or unlock styles incorrectly.
- `src/domain/flames.ts` because Flame catalog must match the 20 Appendix A flames with exact unlock conditions and Amber as the only free style.
- `src/components/Bonfire/flameModel.ts` because Maps fire state to flame rendering parameters; the spec forbids any quality-reduction or device-tiered degradation path.
- `src/components/Bonfire/Flame.tsx` because Renders the flame at full design fidelity with Skia and Reanimated, where fidelity takes precedence over frame rate.
- `src/components/Bonfire/Embers.tsx` because Ember rendering is part of the full-fidelity flame scene and must not be simplified or tiered by device.
- `src/components/Bonfire/FireScene.tsx` because Composes the night scene and flame; it must match the BonfireDesign reference and honor reduced-motion without dropping visual detail otherwise.
- `src/data/entriesStore.ts` because Persists the local score history that every fire and achievement state is derived from; corruption loses user data.
- `src/data/settingsStore.ts` because Persists the selected flame and color across restarts; its stored shape must stay migration-safe for existing installs.
- `src/hooks/useSettings.ts` because Gates the loading placeholder until entries and settings are ready, preventing a premature unlit flash.
- `src/screens/BonfireScreen.tsx` because Main screen wires the flame, out state, loading placeholder, and calendar swipe gesture together.
- `src/components/Calendar/CalendarSheet.tsx` because Enforces no future-date scoring and backward-only month paging, which are core product rules.
- `src/components/Calendar/ScorePickerBar.tsx` because Score entry control that must reject future dates and keep accessible touch targets.
- `src/theme/palettes.ts` because Holds the flame color palettes that must match the design reference exactly.
- `src/domain/fire.ts` because Pure fire engine that is the test oracle for fire state; contract forbids I/O, React, or Date.now(), so changes can silently alter every derived fire state.
- `src/data/entriesStore.ts` because Sole persistence boundary for scores and notes; the contract requires loadEntries never to throw and a round trip to deep-equal saved data.
- `src/data/settingsStore.ts` because Persists the flame color preference; the contract requires invalid values to fall back to Amber and round trips to be exact.
- `src/hooks/useEntries.ts` because Enforces score validation (1..5, no future dates) and ordered persistence, and derives fire via useMemo; contract-mandated behavior lives here.
- `src/components/Bonfire/flameModel.ts` because Pure flame math with contract guarantees (intensity(0)===0, strict monotonicity, soft cap) checked by flameModel.test.ts.
- `src/domain/achievements.ts` because Derives unlockable flame styles from streak and time thresholds; changes can revoke or grant user progress.
- `src/domain/flames.ts` because Flame style catalog that achievements and settings depend on; renaming or removing ids breaks saved selections.
- `src/hooks/useSettings.ts` because Validates the flame color enum and persists it; flagged for ownership risk and tied to FR 016/017.
- `src/theme/palettes.ts` because Palettes are ported from the design source for visual parity; edits change the flame look that the spec and design expect.
- `src/components/Calendar/CalendarSheet.tsx` because Hosts the swipe-up calendar that is the only UI path for logging, editing, and clearing scores, so regressions block core use.
- `src/screens/BonfireScreen.tsx` because Top-level screen wiring stores, hooks, and the Skia scene together; flagged by analysis for import-cycle and ownership risk.
- `jest.setup.js` because Global test environment setup (including AsyncStorage mocking the contract tests rely on); changes can make all tests pass or fail spuriously.

## Never-Touch Paths

- `specs/**/contracts/**` because Frozen contracts are the authoritative interface definitions for the fire engine, stores, and flame gallery, and automated edits could silently change required behavior.
- `**/.env*` because secrets must never be modified by Gardener.
- `**/secrets/**` because secret material requires human handling.
- `gardener/**` because Gardener's own rules change only through a reviewed constitution PR.
- `GARDENER.md` because Gardener's own rules change only through a reviewed constitution PR.
- `specs/**` because the product specs are the source of truth Gardener checks code against.
- `specs/**` because Product specs and contracts are the authoritative statement of scope and fix policy and are maintained by humans.
- `.agents/skills/**` because Agent skill files define project workflow instructions and are not application code.
- `.claude/skills/**` because Agent skill files define project workflow instructions and must stay in sync with the spec kit tooling.
- `src/data/**/v1 storage key literal` because The versioned AsyncStorage key is the migration anchor for saved scores; renaming it without a migration loses user data.

## Autonomous Fixes Allowed

- `lint_format`: kept from the current constitution
- Under the current no_autonomy classification, make no autonomous code changes; only report findings.
- If autonomy is later permitted, limit to prettier formatting and eslint --fix on non-protected files under src/components/Settings or __tests__ with no behavior change.

## Assisted Fixes Allowed

- `dependency_patch`: kept from the current constitution
- `tests`: Adding Jest tests under __tests__ for fire rules, achievements, and calendar constraints is low risk and does not change app behavior
- `complexity_reduction`: Simplifying functions in fire.ts, achievements.ts, or flameModel.ts can subtly change deterministic results and needs a human to confirm spec rules still hold
- Type-level fixes under strict TypeScript that preserve runtime behavior in src/components and src/hooks, reviewed by a maintainer.
- Adding missing unit tests for contract guarantees (for example, fire.ts behavior table rows or settingsStore invalid-color fallback) without changing production logic.
- Dependency patch updates for jest-expo, eslint-config-expo, or @types packages, verified by the full test run.

## Advisory-Only Areas

- `migrations`: kept from the current constitution
- Fire scoring rules (gap tolerance, strength contribution curve, extinguish policy) because they are product decisions defined in the spec.
- Skia and Reanimated rendering performance on device, which needs manual inspection.
- Achievement thresholds and unlock timing for collectible flame styles.
- Fire Health labels (Faint, Steady, Bright, Radiant) and atmosphere tuning from local time.

## Architecture Boundaries

- The fire engine in src/domain/fire.ts (computeFire) must be pure and framework-free: no I/O, no React, no formatting, no per-day contribution maps, and no Date.now() inside (today is passed in). (sources: specs/001-bonfire-productivity-tracker/contracts/fire-engine.md#Contract: Fire Engine (`src/domain/fire.ts`))
- The rest of the app must never touch AsyncStorage directly; all persistence is isolated in the data layer (entriesStore.ts and settingsStore.ts) behind hooks. (sources: specs/001-bonfire-productivity-tracker/contracts/entries-store.md#Contract: Entries Store (`src/data/entriesStore.ts`) & `u...; specs/001-bonfire-productivity-tracker/plan.md#Constitution Check)
- Persistence lives in src/data and rendering lives in src/components. (sources: specs/001-bonfire-productivity-tracker/contracts/fire-engine.md#Contract: Fire Engine (`src/domain/fire.ts`))
- The flame model and theme files must contain only pure mapping and constants; animation lives in Flame.tsx/Embers.tsx and palette persistence in settingsStore. (sources: specs/001-bonfire-productivity-tracker/contracts/flame-and-theme.md#Contract: Flame Model & Theme (`src/components/Bonfire/fl...)
