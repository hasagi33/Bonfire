# Gardener Rules

## Protected Modules

- `src/domain/achievements.ts` because Achievement unlock rules and time-window logic define which flames are earned, and the spec requires them preserved unchanged.
- `src/domain/*.ts` because Pure fire strength, run, and metric math (including the two-missed-days rule) is the deterministic core that the spec says must not change.
- `src/domain/flames.ts` because The 20-flame catalog ties each flame to its achievement and identity, so edits can silently change unlock requirements or flame identities.
- `src/theme/palettes.ts` because Palette helpers withAlpha and darken must be pure, deterministic, never throw on malformed hex (black fallback), and glow colors must be memoized rather than computed per frame. (from specs/003-ui-flame-polish/contracts/glow-derivation.md#Contract: Palette-Derived Glow (palettes.ts + fire scene))
- `src/components/Bonfire/flameModel.ts` because Maps flame styles to visual profiles and the embered variant; the spec requires each flame's identity to be preserved in rendering.
- `src/components/Bonfire/FireScene.tsx` because Composes the Skia flame scene, reduced-motion handling, and the soft-capped on-screen size, all of which have explicit spec constraints.
- `src/components/Bonfire/Flame.tsx` because Core Skia flame renderer whose output must match BonfireDesign profiles and keep the ≥120 FPS target during recolor.
- `src/components/Calendar/ScorePickerBar.tsx` because Holds the fixed per-score button colors (1 white through 5 red) and the score-1 outline that the heat ramp contract specifies.
- `src/components/Calendar/CalendarSheet.tsx` because Calendar sheet gesture handling is critical: the new down-only sheet-body pan must not steal sub-threshold taps on day cells, score buttons, Clear, or month-nav arrows. (from specs/003-ui-flame-polish/contracts/gesture-surface.md#Contract: Calendar Gesture Surfaces + Cog Target)
- `src/components/Settings/FlameGallery.tsx` because Enforces the locked-flame selection guard and rejection feedback; the spec requires locked flames to never be equippable.
- `src/hooks/useSettings.ts` because Persists the selected flame and color across restarts, so changes can break the stored-selection contract.
- `src/data/settingsStore.ts` because Storage schema for the persisted flame and color selection; the spec requires schema and storage behavior to stay unchanged.
- `src/screens/BonfireScreen.tsx` because The equip wrapper must ignore locked flame ids so a locked equip is never persisted (defense in depth), and the screen must pass the palette to Hearth. (from specs/003-ui-flame-polish/contracts/locked-selection.md#Contract: Locked-Flame Selection Guard)
- `src/components/Settings/SettingsSheet.tsx` because The settings gear must stay 52x52 pt (at least the 44 pt minimum touch target) and keep zIndex above the full-screen gesture overlay so its taps always win. (from specs/003-ui-flame-polish/contracts/gesture-surface.md#Contract: Calendar Gesture Surfaces + Cog Target)
- `src/theme/tokens.ts` because Heat ramp tokens are the single source of truth for score buttons and day cells; heat5 must pass the 4.5:1 contrast guarantee and heat1 must be pure white with a border. (from specs/003-ui-flame-polish/contracts/score-heat-ramp.md#Contract: Score Heat Ramp (tokens.ts))
- `src/components/Settings/FlameRow.tsx` because Locked flame rows must not invoke the equip callback; equip is allowed only when the flame is unlocked, and rejection must give a brief cue with disabled accessibility state. (from specs/003-ui-flame-polish/contracts/locked-selection.md#Contract: Locked-Flame Selection Guard)
- `src/hooks/useFlames.ts` because Flame unlock and selection flow must keep its existing behavior; adding visual profiles must not change unlock state or stored selection. (from specs/004-flame-visual-profiles/spec.md#User Story 3 - Particles and Aura Match Each Flame (Prior...)
- `src/domain/fire.ts` because Pure fire engine that is the test oracle for fire state; contract forbids I/O, React, or Date.now(), so changes can silently alter every derived fire state.
- `src/data/entriesStore.ts` because Sole persistence boundary for scores and notes; the contract requires loadEntries never to throw and a round trip to deep-equal saved data.
- `src/hooks/useEntries.ts` because Enforces score validation (1..5, no future dates) and ordered persistence, and derives fire via useMemo; contract-mandated behavior lives here.
- `jest.setup.js` because Global test environment setup (including AsyncStorage mocking the contract tests rely on); changes can make all tests pass or fail spuriously.

## Never-Touch Paths

- `specs/**` because Product specs are the authoritative statement of scope and fix policy; automated changes must not rewrite them.
- `gardener/**` because Holds the maintenance tool's own policy and configuration; self-modification would bypass the policy it enforces.
- `BonfireDesign/` because BonfireDesign/ is the authoritative design reference and must not be modified by the spec 004 work; it is the source of truth for product flame parity. (from specs/004-flame-visual-profiles/plan.md#Implementation Plan: Flame Visual Profiles)
- `src/domain/fireStrength.ts` because Fire Health must not change fire strength math, so the fire strength calculation must not be modified by the Fire Health work. (from specs/007-fire-health/contracts/fire-health-behavior.md#Fire Health Behavior Contract)
- `**/.env*` because secrets must never be modified by Gardener.
- `**/secrets/**` because secret material requires human handling.
- `GARDENER.md` because Gardener's own rules change only through a reviewed constitution PR.
- `.agents/skills/**` because Agent skill files define project workflow instructions and are not application code.
- `.claude/skills/**` because Agent skill files define project workflow instructions and must stay in sync with the spec kit tooling.
- `src/data/**/v1 storage key literal` because The versioned AsyncStorage key is the migration anchor for saved scores; renaming it without a migration loses user data.

## Autonomous Fixes Allowed

- `lint_format`: kept from the current constitution
- Under the current no_autonomy classification, make no autonomous code changes; only report findings.
- If autonomy is later permitted, limit to prettier formatting and eslint --fix on non-protected files under src/components/Settings or __tests__ with no behavior change.

## Assisted Fixes Allowed

- `dependency_patch`: kept from the current constitution
- `tests`: Adding characterization tests for pure domain logic (fireMetrics, achievements, flame catalog) is low-risk and verifiable with the existing Jest suite
- `complexity_reduction`: Large rendering and sheet components are candidates for simplification, but they carry visual, gesture, and performance constraints that need human review
- Type-level fixes under strict TypeScript that preserve runtime behavior in src/components and src/hooks, reviewed by a maintainer.
- Adding missing unit tests for contract guarantees (for example, fire.ts behavior table rows or settingsStore invalid-color fallback) without changing production logic.
- Dependency patch updates for jest-expo, eslint-config-expo, or @types packages, verified by the full test run.

## Advisory-Only Areas

- `migrations`: The AsyncStorage schema for scores, notes, and flame selection is persisted user data; any schema change should be advised on, not auto-applied
- Fire scoring rules (gap tolerance, strength contribution curve, extinguish policy) because they are product decisions defined in the spec.
- Skia and Reanimated rendering performance on device, which needs manual inspection.
- Achievement thresholds and unlock timing for collectible flame styles.
- Fire Health labels (Faint, Steady, Bright, Radiant) and atmosphere tuning from local time.
