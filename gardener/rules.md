# Gardener Rules

## Protected Modules

- `src/domain/achievements.ts` because Unlock states must be derived deterministically from the full score calendar and current date, never stored, so changes here can silently break relock and time-window rules.
- `src/components/Bonfire/flameModel.ts` because The flame visual mapping must keep intensity strictly increasing with a soft cap and height non-decreasing in strength for lit fires, and it must match the design-derived constants. (from specs/001-bonfire-productivity-tracker/contracts/flame-and-theme.md#Contract: Flame Model & Theme (`src/components/Bonfire/fl...)
- `src/theme/palettes.ts` because Palette and theme color sources must stay centralized; per-flame glow and particle colors derive from these values.
- `src/hooks/useSettings.ts` because Controls persistence of the chosen flame color with an Amber default across restarts, a user-facing persisted setting.
- `src/screens/BonfireScreen.tsx` because Holds the cold-start loading placeholder and the rule that a tap is not overwritten by the load, plus the swipe-up calendar entry point.
- `src/components/Calendar/ScorePickerBar.tsx` because Score buttons have fixed distinct colors per value (1 white through 5 red) and a distinguishable selected state specified by the product.
- `src/components/Settings/FlameGallery.tsx` because Locked flames must be rejected on tap with a visible cue, and equipped locked flames must render embered; regressions here break the selection guard.
- `src/data/entriesStore.ts` because The entries store is the only persistence layer for scores; it must never throw, must round-trip data exactly, and uses a versioned storage key so schema changes can be migrated. (from specs/001-bonfire-productivity-tracker/contracts/entries-store.md#Contract: Entries Store (`src/data/entriesStore.ts`) & `u...)
- `src/data/settingsStore.ts` because The settings store must never throw, falls back to Amber on invalid color, and must round-trip settings exactly. (from specs/001-bonfire-productivity-tracker/contracts/settings-store.md#Contract: Settings Store (`src/data/settingsStore.ts`) &...)
- `src/hooks/useEntries.ts` because Enforces score validation (1..5, no future dates) and ordered persistence, and derives fire via useMemo; contract-mandated behavior lives here.
- `src/domain/flames.ts` because Flame style catalog that achievements and settings depend on; renaming or removing ids breaks saved selections.
- `jest.setup.js` because Global test environment setup (including AsyncStorage mocking the contract tests rely on); changes can make all tests pass or fail spuriously.

## Never-Touch Paths

- `specs/**` because Product specs and contracts are the authoritative statement of scope and fix/no-fix policy and must not be edited by automated changes.
- `gardener/**` because This is the maintenance tooling itself; automated changes should not modify the policy engine that governs them.
- `src/domain/fire.ts` because src/domain/fire.ts must not be modified by the Fire Health work because fire strength math must stay unchanged. (from specs/007-fire-health/contracts/fire-health-behavior.md#Fire Health Behavior Contract)
- `src/domain/flames.ts` because src/domain/flames.ts is the designed editing surface for flame unlock conditions and is referenced only as a dev aid; the spec does not authorize changing its rules as part of this feature. (from specs/003-ui-flame-polish/quickstart.md#Quickstart: UI & Flame Polish Fixes)
- `**/.env*` because secrets must never be modified by Gardener.
- `**/secrets/**` because secret material requires human handling.
- `GARDENER.md` because Gardener's own rules change only through a reviewed constitution PR.
- `.agents/skills/**` because Agent skill files define project workflow instructions and are not application code.
- `.claude/skills/**` because Agent skill files define project workflow instructions and must stay in sync with the spec kit tooling.
- `src/data/**/v1 storage key literal` because The versioned AsyncStorage key is the migration anchor for saved scores; renaming it without a migration loses user data.
- `legal/qa-cod120-counsel/**` because outside counsel owns these contract drafts; they must stay byte-identical.

## Autonomous Fixes Allowed

- `lint_format`: kept from the current constitution
- Under the current no_autonomy classification, make no autonomous code changes; only report findings.
- If autonomy is later permitted, limit to prettier formatting and eslint --fix on non-protected files under src/components/Settings or __tests__ with no behavior change.

## Assisted Fixes Allowed

- `dependency_patch`: kept from the current constitution
- `tests`: Adding unit tests for pure domain logic (fireMetrics, flameModel, achievements, flame catalog) is low-risk and verifiable with the existing Jest setup
- `complexity_reduction`: Components mixing Skia rendering, Reanimated worklets, and gesture handling are sensitive to timing and visual output, so simplifications need human review of rendering behavior
- Type-level fixes under strict TypeScript that preserve runtime behavior in src/components and src/hooks, reviewed by a maintainer.
- Adding missing unit tests for contract guarantees (for example, fire.ts behavior table rows or settingsStore invalid-color fallback) without changing production logic.
- Dependency patch updates for jest-expo, eslint-config-expo, or @types packages, verified by the full test run.

## Advisory-Only Areas

- `api_behavior`: kept from the current constitution
- `migrations`: kept from the current constitution
- Fire scoring rules (gap tolerance, strength contribution curve, extinguish policy) because they are product decisions defined in the spec.
- Skia and Reanimated rendering performance on device, which needs manual inspection.
- Achievement thresholds and unlock timing for collectible flame styles.
- Fire Health labels (Faint, Steady, Bright, Radiant) and atmosphere tuning from local time.

## Architecture Boundaries

- The rest of the app must never touch AsyncStorage directly; all score persistence is isolated in the entries store. (sources: specs/001-bonfire-productivity-tracker/contracts/entries-store.md#Contract: Entries Store (`src/data/entriesStore.ts`) & `u...)
- The fire engine must remain framework-free with no persistence, formatting, React state, or Date.now() inside (today is passed in), and must not import React Native, Skia, or storage modules; persistence lives in data/ and rendering in components/. (sources: specs/001-bonfire-productivity-tracker/contracts/fire-engine.md#Contract: Fire Engine (`src/domain/fire.ts`); specs/001-bonfire-productivity-tracker/plan.md#Constitution Check)
- Theme palettes and tokens are ported from the design, and the flame gradient stops must come from the active palette so switching palette recolors the flame immediately. (sources: specs/001-bonfire-productivity-tracker/contracts/flame-and-theme.md#Contract: Flame Model & Theme (`src/components/Bonfire/fl...)
- Flame intensity uses the exponential curve 1 - e^(-strength/14), ported verbatim into flameModel.ts so the React Native flame scales like the design. (sources: specs/001-bonfire-productivity-tracker/research.md#Phase 0 Research: Bonfire Productivity Tracker (design-fa...)
- The app must reject scores outside the integer range 1-5 and must reject scores for future dates. (sources: specs/001-bonfire-productivity-tracker/spec.md#Edge Cases)
- A score of 1 counts the day as active (keeping the fire alive) but adds no strength; scores 2-5 add strictly increasing strength, and any score relights an extinguished fire. (sources: specs/001-bonfire-productivity-tracker/spec.md#Edge Cases)
- The fire's total strength must equal the cumulative sum of strength contributions of every scored day in the current lit run. (sources: specs/001-bonfire-productivity-tracker/spec.md#Edge Cases)
- A single missed past day must not cause the fire to go out, but two consecutive missed past calendar days must cause the fire to go out, resetting strength to zero; the next logged score starts a new fire from zero. (sources: specs/001-bonfire-productivity-tracker/spec.md#User Story 2 - Keep the streak alive (fire goes out after...)
