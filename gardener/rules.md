# Gardener Rules

## Protected Modules

- `src/domain/achievements.ts` because Derives streak and time achievement unlocks from the calendar; the D+W window, no-banking, and order-independent recomputation rules are spec-defined.
- `src/domain/flames.ts` because Catalog changes must keep unique ids, exactly one base flame, strictly increasing rarity, a windowDays on every time achievement only, and no banned low-score or intentional streak-break conditions. (from specs/002-achievement-flame-unlocks/contracts/flame-catalog.md#Contract: Flame Catalog (`src/domain/flames.ts` + `src/th...)
- `src/components/Bonfire/flameModel.ts` because Also shared by fire-state logic: scores 1-5 as integers, two consecutive misses extinguish, and today being unscored is not a miss.
- `src/components/Bonfire/Flame.tsx` because Renders the flame, including the dim embered variant for locked styles, where Amber must never render embered and the 120 FPS target applies.
- `src/components/Bonfire/Embers.tsx` because Skia/Reanimated ember rendering on the frame-timing path; the spec requires at least 120 FPS on 120 Hz devices for every style, including multicolor ones.
- `src/components/Bonfire/FireScene.tsx` because Composes the out-state visuals (charred logs, smoke wisp), which take precedence over any equipped flame style per spec.
- `src/screens/BonfireScreen.tsx` because Owns the full-screen upward swipe to open the calendar while taps on the gear, dev pill, and day cells must keep working unchanged.
- `src/hooks/useSettings.ts` because Persists the selected flame and color across restarts with Amber as default; the spec requires this persistence behavior.
- `src/theme/palettes.ts` because Defines the Amber, Crimson, and Sapphire palettes; changing values recolors every flame and is spec-visible.
- `src/components/Calendar/CalendarSheet.tsx` because Score entry, editing, and clearing for past and current days; it must not allow future dates and must trigger recomputation.
- `src/components/Settings/FlameGallery.tsx` because Shows unlock status, requirements, and live progress or window countdowns that must match the derived achievement state.
- `src/**/palettes.ts` because Palette derivation helpers and glow stops affect how every flame renders; changes need human review. (from specs/003-ui-flame-polish/research.md#Research: UI & Flame Polish Fixes)
- `src/**/tokens.ts` because Heat tokens are the single source for score colors shared by picker and day cells; changes need human review. (from specs/003-ui-flame-polish/research.md#R3. Score heat ramp white→red (P3))
- `BonfireDesign/flame-profiles.js` because Source data map for the 20 flame profiles that all visual profile data must be derived from; changes need review because product profiles trace to it. (from specs/004-flame-visual-profiles/contracts/visual-profile-data.md#Contract: Visual Profile Data)
- `BonfireDesign/flame-renderer.jsx` because Reference for expected generic token behavior that the Skia renderer must reproduce. (from specs/004-flame-visual-profiles/contracts/visual-profile-data.md#Contract: Visual Profile Data)
- `BonfireDesign/flame-catalog.css` because Reference for expected visual behavior of aura, accents, particles, edge treatments, and motion families. (from specs/004-flame-visual-profiles/contracts/visual-profile-data.md#Contract: Visual Profile Data)
- `BonfireDesign/screenshots/*` because Visual review references used to compare product flames against the design. (from specs/004-flame-visual-profiles/contracts/visual-profile-data.md#Contract: Visual Profile Data)
- `src/domain/fire.ts` because Pure fire engine that is the test oracle for fire state; contract forbids I/O, React, or Date.now(), so changes can silently alter every derived fire state.
- `src/data/entriesStore.ts` because Sole persistence boundary for scores and notes; the contract requires loadEntries never to throw and a round trip to deep-equal saved data.
- `src/data/settingsStore.ts` because Persists the flame color preference; the contract requires invalid values to fall back to Amber and round trips to be exact.
- `src/hooks/useEntries.ts` because Enforces score validation (1..5, no future dates) and ordered persistence, and derives fire via useMemo; contract-mandated behavior lives here.
- `src/components/Bonfire/flameModel.ts` because Pure flame math with contract guarantees (intensity(0)===0, strict monotonicity, soft cap) checked by flameModel.test.ts.
- `src/domain/achievements.ts` because Derives unlockable flame styles from streak and time thresholds; changes can revoke or grant user progress.
- `src/domain/flames.ts` because Flame style catalog that achievements and settings depend on; renaming or removing ids breaks saved selections.
- `src/hooks/useSettings.ts` because Validates the flame color enum and persists it; flagged for ownership risk and tied to FR 016/017.
- `src/theme/palettes.ts` because Palettes are ported from the design source for visual parity; edits change the flame look that the spec and design expect.
- `src/components/Calendar/CalendarSheet.tsx` because Hosts the swipe-up calendar that is the only UI path for logging, editing, and clearing scores, so regressions block core use.
- `src/screens/BonfireScreen.tsx` because Top-level screen wiring stores, hooks, and the Skia scene together; flagged by analysis for import-cycle and ownership risk.
- `jest.setup.js` because Global test environment setup (including AsyncStorage mocking the contract tests rely on); changes can make all tests pass or fail spuriously.

## Never-Touch Paths

- `specs/**/contracts/**` because Frozen contract documents that are the authoritative statement of store and component behavior; automated changes must not edit them.
- `specs/**/spec.md` because Product specifications are the authoritative scope and fix/no-fix policy and must be changed only by humans.
- `gardener/**` because The maintenance tool's own directory; automated changes must not modify the policy engine that governs them.
- `src/domain/fire.ts` because fire.ts must not be modified by the achievement engine work; the engine reuses its computeFire rules without changing them. (from specs/002-achievement-flame-unlocks/contracts/achievement-engine.md#Contract: Achievement Engine (`src/domain/fireMetrics.ts`...)
- `**/.env*` because secrets must never be modified by Gardener.
- `**/secrets/**` because secret material requires human handling.
- `specs/**` because Product specs and contracts are the authoritative statement of scope and fix policy and are maintained by humans.
- `.agents/skills/**` because Agent skill files define project workflow instructions and are not application code.
- `.claude/skills/**` because Agent skill files define project workflow instructions and must stay in sync with the spec kit tooling.
- `src/data/**/v1 storage key literal` because The versioned AsyncStorage key is the migration anchor for saved scores; renaming it without a migration loses user data.

## Autonomous Fixes Allowed

- `lint_format`: kept from the current constitution
- Under the current no_autonomy classification, make no autonomous code changes; only report findings.
- If autonomy is later permitted, limit to prettier formatting and eslint --fix on non-protected files under src/components/Settings or __tests__ with no behavior change.

## Assisted Fixes Allowed

- `dependency_patch`: kept from the current constitution
- `tests`: Adding unit tests for pure domain logic (fireMetrics, achievements, flame catalog) is low risk, and the existing __tests__ suite gives a clear pattern to follow
- `complexity_reduction`: Splitting functions in fire, achievement, or flame logic can silently change spec-defined behavior, so a maintainer should review each diff
- Type-level fixes under strict TypeScript that preserve runtime behavior in src/components and src/hooks, reviewed by a maintainer.
- Adding missing unit tests for contract guarantees (for example, fire.ts behavior table rows or settingsStore invalid-color fallback) without changing production logic.
- Dependency patch updates for jest-expo, eslint-config-expo, or @types packages, verified by the full test run.

## Advisory-Only Areas

- `requirement_mismatch`: Code that diverges from spec rules (strength values, D+W window, 120 FPS) should be reported for a human to decide, not auto-fixed, because the spec is authoritative
- Fire scoring rules (gap tolerance, strength contribution curve, extinguish policy) because they are product decisions defined in the spec.
- Skia and Reanimated rendering performance on device, which needs manual inspection.
- Achievement thresholds and unlock timing for collectible flame styles.
- Fire Health labels (Faint, Steady, Bright, Radiant) and atmosphere tuning from local time.

(sources: specs/001-bonfire-productivity-tracker/contracts/entries-store.md#Contract: Entries Store (`src/data/entriesStore.ts`) & `u...; specs/001-bonfire-productivity-tracker/plan.md#Constitution Check)

(sources: specs/001-bonfire-productivity-tracker/contracts/fire-engine.md#Contract: Fire Engine (`src/domain/fire.ts`); specs/001-bonfire-productivity-tracker/plan.md#Constitution Check; specs/001-bonfire-productivity-tracker/research.md#Phase 0 Research: Bonfire Productivity Tracker (design-fa...; +1 more)
