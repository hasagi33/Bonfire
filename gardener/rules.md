# Gardener Rules

## Protected Modules

- `src/domain/achievements.ts` because Derives streak and time flame unlocks from the calendar, and the spec requires this logic to be deterministic, order-independent, and free of banking.
- `src/domain/flames.ts` because Catalog changes must keep unique ids, exactly one base flame, strictly increasing rarity, a windowDays on every time achievement only, and no banned low-score or intentional streak-break conditions. (from specs/002-achievement-flame-unlocks/contracts/flame-catalog.md#Contract: Flame Catalog (`src/domain/flames.ts` + `src/th...)
- `src/components/Bonfire/flameModel.ts` because Computes flame strength and size, including the soft cap and the 0/1/2-5 score contribution rules that the spec defines.
- `src/data/entriesStore.ts` because Persists scores locally and enforces integer 1-5 range and no future dates, as defined by the entries-store contract.
- `src/hooks/useSettings.ts` because Persists the active flame selection across restarts, defaulting to Amber, as defined by the settings-store contract.
- `src/theme/palettes.ts` because Defines flame color palettes (Amber, Crimson, Sapphire and others); changes alter the visible flame identity and locked embered variants.
- `src/screens/BonfireScreen.tsx` because Hosts the cold-start loading gate, the no-unlit-flash rule, and the swipe-up calendar and gear tap coexistence.
- `src/components/Calendar/CalendarSheet.tsx` because Gesture-driven calendar sheet where past-day score edits trigger fire recomputation; gesture changes risk breaking taps on day cells.
- `src/components/Settings/FlameGallery.tsx` because Shows unlock status, requirements, and live progress for every flame; mistakes here misreport achievement state to users.
- `src/**/palettes.ts` because Palette derivation helpers and glow stops affect how every flame renders; changes need human review. (from specs/003-ui-flame-polish/research.md#Research: UI & Flame Polish Fixes)
- `src/**/tokens.ts` because Heat tokens are the single source for score colors shared by picker and day cells; changes need human review. (from specs/003-ui-flame-polish/research.md#R3. Score heat ramp white→red (P3))
- `BonfireDesign/flame-profiles.js` because Source data map for the 20 flame profiles that all visual profile data must be derived from; changes need review because product profiles trace to it. (from specs/004-flame-visual-profiles/contracts/visual-profile-data.md#Contract: Visual Profile Data)
- `BonfireDesign/flame-renderer.jsx` because Reference for expected generic token behavior that the Skia renderer must reproduce. (from specs/004-flame-visual-profiles/contracts/visual-profile-data.md#Contract: Visual Profile Data)
- `BonfireDesign/flame-catalog.css` because Reference for expected visual behavior of aura, accents, particles, edge treatments, and motion families. (from specs/004-flame-visual-profiles/contracts/visual-profile-data.md#Contract: Visual Profile Data)
- `BonfireDesign/screenshots/*` because Visual review references used to compare product flames against the design. (from specs/004-flame-visual-profiles/contracts/visual-profile-data.md#Contract: Visual Profile Data)

## Never-Touch Paths

- `specs/**/contracts/**` because Frozen product contracts that define scope and fix policy; automated edits would silently change the agreed behavior.
- `specs/**/spec.md` because Authoritative feature specifications; they must only be changed by humans through the spec workflow.
- `src/domain/fire.ts` because fire.ts must not be modified by the achievement engine work; the engine reuses its computeFire rules without changing them. (from specs/002-achievement-flame-unlocks/contracts/achievement-engine.md#Contract: Achievement Engine (`src/domain/fireMetrics.ts`...)
- `**/.env*` because secrets must never be modified by Gardener.
- `**/secrets/**` because secret material requires human handling.

## Autonomous Fixes Allowed

- `lint_format`: kept from the current constitution

## Assisted Fixes Allowed

- `dependency_patch`: kept from the current constitution
- `tests`: Adding tests for pure domain logic (fire metrics, flame model, achievements, catalog) is low risk and does not change runtime behavior
- `complexity_reduction`: Splitting overly complex components like the calendar sheet or flame rendering can subtly change gesture or render behavior, so a reviewer should confirm equivalence

## Advisory-Only Areas

- `requirement_mismatch`: Fire strength, two-miss extinguish, and time-window rules are spec-defined; the tool should flag mismatches for human judgment rather than rewrite them
