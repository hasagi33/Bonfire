# Gardener Rules

## Protected Modules

- `src/domain/achievements.ts` because Holds the achievement conditions that gate every flame unlock, so changes can silently change which flames are earnable.
- `src/domain/flames.ts` because Defines the flame catalog and each flame's unlock mapping; the spec fixes the catalog contents and Amber as the only free flame.
- `src/components/Bonfire/flameModel.ts` because Derives flame state (lit, out, embered, unlocked) that the spec requires to be deterministic and order-independent.
- `src/hooks/useSettings.ts` because Persists the selected flame and settings across restarts; a change here can break stored-state compatibility and the default Amber selection.
- `src/components/Bonfire/Flame.tsx` because Halo, ground glow and tongue-base colors must derive from the active palette, not hardcoded RGBA, and derived arrays must be memoized per palette, never recomputed per frame. (from specs/003-ui-flame-polish/contracts/glow-derivation.md#Contract: Palette-Derived Glow (palettes.ts + fire scene))
- `src/components/Bonfire/FireScene.tsx` because Composes the bonfire scene; it must keep the out-state precedence and the clean default view (flame and settings button only).
- `src/components/Calendar/CalendarSheet.tsx` because The new down-only pan must activate after about 12px and must not steal plain taps on day cells, score buttons, Clear, or month-nav arrows; up-swipe while open and down-swipe while closed are no-ops. (from specs/003-ui-flame-polish/contracts/gesture-surface.md#Contract: Calendar Gesture Surfaces + Cog Target)
- `src/screens/BonfireScreen.tsx` because The equip wrapper must ignore locked flame ids and only persist unlocked ids; the progress value stays the single shared 0-to-1 value and the flame lift/dim lock-step is untouched. (from specs/003-ui-flame-polish/contracts/locked-selection.md#Contract: Locked-Flame Selection Guard)
- `src/theme/palettes.ts` because Glow derivation must reproduce today's default Amber look (regression guarantee) and never throw on malformed hex, falling back to black like parseHex. (from specs/003-ui-flame-polish/contracts/glow-derivation.md#Contract: Palette-Derived Glow (palettes.ts + fire scene))
- `src/components/Settings/FlameGallery.tsx` because Shows unlock status, requirements, and live progress; the spec defines exactly what the gallery must display.
- `__tests__/fireMetrics.test.ts` because Encodes the spec rules for score-to-strength ordering and the one-day-missed versus two-day-missed behavior; these tests must not be weakened.
- `__tests__/achievements.test.ts` because Verifies achievement unlock and time-window rules that the spec makes authoritative.
- `__tests__/flameModel.test.ts` because Verifies flame state derivation including embered and out-state rules.
- `__tests__/flames.catalog.test.ts` because Verifies the catalog contents and Amber-as-free rule from the spec.
- `__tests__/CalendarSheet.test.tsx` because Verifies calendar gesture and no-future-month behavior from the spec.
- `__tests__/BonfireScreen.test.tsx` because Verifies the main view, loading placeholder, and settings behavior.
- `jest.setup.js` because Shared Jest setup for Skia, Reanimated, and AsyncStorage mocks; changes can silently alter what every test exercises.
- `src/components/Bonfire/Embers.tsx` because Particle radial fades must derive from each particle's own color and be memoized, with no new JS on the render loop. (from specs/003-ui-flame-polish/contracts/glow-derivation.md#Contract: Palette-Derived Glow (palettes.ts + fire scene))
- `src/components/Bonfire/Hearth.tsx` because Warm wash and coal colors must derive from the palette prop passed by BonfireScreen. (from specs/003-ui-flame-polish/contracts/glow-derivation.md#Contract: Palette-Derived Glow (palettes.ts + fire scene))
- `src/theme/tokens.ts` because heat1 must be pure white, heat5 red, and every score's text must meet at least 4.5:1 contrast against its background; heatStyle(1) carries a border while 2 to 5 do not. (from specs/003-ui-flame-polish/contracts/score-heat-ramp.md#Contract: Score Heat Ramp (tokens.ts))
- `src/components/Settings/SettingsSheet.tsx` because The gear must be 52x52 pt with the icon at size 26, keep its position and open FlameGallery, and stay above the gesture overlay via zIndex. (from specs/003-ui-flame-polish/contracts/gesture-surface.md#Contract: Calendar Gesture Surfaces + Cog Target)
- `src/components/Settings/FlameRow.tsx` because Locked rows must not call onPress, must play the rejection cue, and must expose accessibilityState disabled with a label stating the locked status. (from specs/003-ui-flame-polish/contracts/locked-selection.md#Contract: Locked-Flame Selection Guard)
- `src/components/Calendar/ScorePickerBar.tsx` because The white score-1 button must keep a visible outline so it reads on light surfaces. (from specs/003-ui-flame-polish/contracts/score-heat-ramp.md#Contract: Score Heat Ramp (tokens.ts))
- `src/domain/fire.ts` because Pure fire engine that is the test oracle for fire state; contract forbids I/O, React, or Date.now(), so changes can silently alter every derived fire state.
- `src/data/entriesStore.ts` because Sole persistence boundary for scores and notes; the contract requires loadEntries never to throw and a round trip to deep-equal saved data.
- `src/data/settingsStore.ts` because Persists the flame color preference; the contract requires invalid values to fall back to Amber and round trips to be exact.
- `src/hooks/useEntries.ts` because Enforces score validation (1..5, no future dates) and ordered persistence, and derives fire via useMemo; contract-mandated behavior lives here.
- `src/components/Bonfire/flameModel.ts` because Pure flame math with contract guarantees (intensity(0)===0, strict monotonicity, soft cap) checked by flameModel.test.ts.
- `src/domain/achievements.ts` because Derives unlockable flame styles from streak and time thresholds; changes can revoke or grant user progress.
- `src/domain/flames.ts` because Flame style catalog that achievements and settings depend on; renaming or removing ids breaks saved selections.
- `src/hooks/useSettings.ts` because Validates the flame color enum and persists it; flagged for ownership risk and tied to FR 016/017.
- `src/theme/palettes.ts` because Palettes are ported from the design source for visual parity; edits change the flame look that the spec and design expect.
- `src/components/Calendar/CalendarSheet.tsx` because Hosts the swipe-up calendar that is the only UI path for logging, editing, and clearing scores, so regressions block core use.
- `src/screens/BonfireScreen.tsx` because Top-level screen wiring stores, hooks, and the Skia scene together; flagged by analysis for import-cycle and ownership risk.
- `jest.setup.js` because Global test environment setup (including AsyncStorage mocking the contract tests rely on); changes can make all tests pass or fail spuriously.

## Never-Touch Paths

- `specs/**` because Product specs and checklists are the authoritative statement of scope and fix policy; automation must not rewrite them.
- `gardener/**` because Maintenance tool's own directory; automated edits could alter the policy that governs those edits.
- `src/domain/streak*` because Streak survival rules must not be changed by Fire Health; the spec forbids altering streak survival rules. (from specs/007-fire-health/spec.md#Feature Specification: Fire Health)
- `**/.env*` because secrets must never be modified by Gardener.
- `**/secrets/**` because secret material requires human handling.
- `GARDENER.md` because Gardener's own rules change only through a reviewed constitution PR.
- `specs/**` because Product specs and contracts are the authoritative statement of scope and fix policy and are maintained by humans.
- `.agents/skills/**` because Agent skill files define project workflow instructions and are not application code.
- `.claude/skills/**` because Agent skill files define project workflow instructions and must stay in sync with the spec kit tooling.
- `src/data/**/v1 storage key literal` because The versioned AsyncStorage key is the migration anchor for saved scores; renaming it without a migration loses user data.

## Autonomous Fixes Allowed

- `lint_format`: kept from the current constitution
- Under the current no_autonomy classification, make no autonomous code changes; only report findings.
- If autonomy is later permitted, limit to prettier formatting and eslint --fix on non-protected files under src/components/Settings or __tests__ with no behavior change.

## Assisted Fixes Allowed

- `dependency_patch`: Changes to the ramp and palette derivation alter user-visible colors and warrant review; no direct autonomous category applies here (source: specs/003-ui-flame-polish/research.md#R3. Score heat ramp white→red (P3))
- `tests`: Adding Jest tests for pure domain logic (fireMetrics, achievements, flameModel, catalog) is low risk and verifiable without touching rendering code
- `complexity_reduction`: Splitting overly complex functions in domain or screen code can drift from spec rules, so each change needs human review and passing spec-derived tests
- Type-level fixes under strict TypeScript that preserve runtime behavior in src/components and src/hooks, reviewed by a maintainer.
- Adding missing unit tests for contract guarantees (for example, fire.ts behavior table rows or settingsStore invalid-color fallback) without changing production logic.
- Dependency patch updates for jest-expo, eslint-config-expo, or @types packages, verified by the full test run.

## Advisory-Only Areas
- Fire scoring rules (gap tolerance, strength contribution curve, extinguish policy) because they are product decisions defined in the spec.
- Skia and Reanimated rendering performance on device, which needs manual inspection.
- Achievement thresholds and unlock timing for collectible flame styles.
- Fire Health labels (Faint, Steady, Bright, Radiant) and atmosphere tuning from local time.
