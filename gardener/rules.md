## Never-Touch Paths

- `specs/**` because Product specs, contracts, and checklists are the authoritative statement of scope and must not be edited by automated maintenance.
- `gardener/**` because The maintenance tool's own configuration and policy must not be modified by the change it governs.
- `BonfireDesign/` because The BonfireDesign/ directory is the canonical design reference bundle and is a build-time reference that should not be altered by automated maintenance; it is read but not shipped. (from specs/001-bonfire-productivity-tracker/plan.md#Implementation Plan: Bonfire Productivity Tracker)
- `src/domain/fire.ts` because src/domain/fire.ts must not be modified; the achievement engine reuses it unchanged and it is the existing fire-state logic. (from specs/002-achievement-flame-unlocks/contracts/achievement-engine.md#Contract: Achievement Engine (`src/domain/fireMetrics.ts`...)
- `src/domain/streak*` because Fire Health must not change streak survival rules, so streak logic must be left unmodified by this feature. (from specs/007-fire-health/contracts/fire-health-behavior.md#Fire Health Behavior Contract)
- `src/domain/fire*` because Fire Health must not change fire strength math, so the fire strength computation must not be modified by this feature. (from specs/007-fire-health/contracts/fire-health-behavior.md#Fire Health Behavior Contract)
- `docs/handbook/**` because The handbook files are published, legally reviewed user-facing text approved by the product owner and store reviewer, so automated tools and bots must never modify them; only the product owner edits them by hand. (from specs/008-user-handbook/spec.md#Feature Specification: User Handbook)
- `**/.env*` because secrets must never be modified by Gardener.
- `**/secrets/**` because secret material requires human handling.
- `GARDENER.md` because Gardener's own rules change only through a reviewed constitution PR.
- `specs/**` because Product specs and contracts are the authoritative statement of scope and fix policy and are maintained by humans.
- `.agents/skills/**` because Agent skill files define project workflow instructions and are not application code.
- `.claude/skills/**` because Agent skill files define project workflow instructions and must stay in sync with the spec kit tooling.
- `src/data/**/v1 storage key literal` because The versioned AsyncStorage key is the migration anchor for saved scores; renaming it without a migration loses user data.

## Autonomous Fixes Allowed

- `lint_format`: kept from the current constitution
- Under the current no_autonomy classification, make no autonomous code changes; only report findings.
- If autonomy is later permitted, limit to prettier formatting and eslint --fix on non-protected files under src/components/Settings or __tests__ with no behavior change.

## Assisted Fixes Allowed

- `dependency_patch`: kept from the current constitution
- `tests`: Adding or fixing Jest tests in __tests__ carries no production behavior change and directly supports the stated verification rules
- `complexity_reduction`: Splitting overly complex functions in the flame, gesture, or domain modules touches protected rendering and gesture logic, so each change needs human review against the spec
- `requirement_mismatch`: Where the design and spec disagree, the spec wins on mechanics and the design wins on look-and-feel; such reconciliations need review (source: specs/001-bonfire-productivity-tracker/plan.md#Implementation Plan: Bonfire Productivity Tracker)
- Type-level fixes under strict TypeScript that preserve runtime behavior in src/components and src/hooks, reviewed by a maintainer.
- Adding missing unit tests for contract guarantees (for example, fire.ts behavior table rows or settingsStore invalid-color fallback) without changing production logic.
- Dependency patch updates for jest-expo, eslint-config-expo, or @types packages, verified by the full test run.

## Advisory-Only Areas
- Fire scoring rules (gap tolerance, strength contribution curve, extinguish policy) because they are product decisions defined in the spec.
- Skia and Reanimated rendering performance on device, which needs manual inspection.
- Achievement thresholds and unlock timing for collectible flame styles.
- Fire Health labels (Faint, Steady, Bright, Radiant) and atmosphere tuning from local time.
